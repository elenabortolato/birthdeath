# Birth–Death Gaussian Graphical Models

Code for *Birth–Death Gaussian Graphical Models for Structurally Evolving
Systems* (Bortolato, Hansen, Rossell). The model is a Gaussian graphical model
whose set of variables changes over time. The precision matrix on the active
set is low rank plus diagonal, and a spike-and-slab prior on rowwise loading
changes, informed by birth and death counts, drives its evolution. Estimation
uses a generalized EM algorithm.

## Setup

Install Julia 1.10 or later, then from the repository root:

```bash
julia --project=. -e 'using Pkg; Pkg.instantiate()'
```

`src/BirthDeathGraphicalModels.jl` loads Plots for its plotting helpers. On a
machine without a display, set `GKSwstype=100` before running.

## Running the experiments

All commands are run from the repository root.

**Experiment II.** One CSV row per simulated trajectory:

```bash
julia --project=. experiments/birthdeath/run_experiment2.jl \
    p=10 seeds=1:20 tau_active=0.75 minimum_active=6 \
    out=results/experiment2/p10_tau075_min6.csv
```

| Argument | Meaning | Default |
|---|---|---|
| `p` | number of variables (10 or 50) | 10 |
| `seeds` | `a:b` range or comma-separated list | `1:5` |
| `tau_active` | fitted active innovation scale τ_a | 0.75 |
| `minimum_active` | lower bound on the number of active variables p_t | k + 1 = 6 |
| `out` | output CSV path | none, prints only |

Every other setting is the paper's, and is fixed in the script.

**Constant precision, p = 5:**

```bash
julia --project=. experiments/constant_precision/run_constant_precision_p5.jl
```

It writes summaries and per-time metrics to
`experiments/constant_precision/constant_precision_p5_output/`.

### Oracle check: why shock detection is poor

`oracle_check.jl` compares the default fit with generalized EM started from the
true parameters ("oracle"). The design is p = 10, τ_a = 1.5 (the true shock
scale) and `minimum_active = 6`, with 20 trajectories per rank. The CSVs are
`results/experiment2/oracle_p10_k*_tau150_min6.csv`.

| | k = 5 | k = 2 |
|---|---|---|
| shock AUROC, oracle / default | 0.99 / 0.60 | 0.94 / 0.59 |
| shock recall, oracle / default | 0.98 / 0.07 | 0.87 / 0.10 |
| off-diagonal RV, oracle / default | 0.86 / 0.70 | 0.94 / 0.78 |
| oracle reaches a higher log posterior than default | 7 of 20 | 17 of 20 |

- Started from the truth, the EM stays there: the data separate shocks from
  non-shocks.
- With k = 2 the decomposition is identified for every p_t ≥ 5. There the
  default fit usually lands in a worse mode than the oracle, so the
  initialization and optimization are what lose the shocks.
- With k = 5 and p_t between 6 and 8 the decomposition is not identified, and
  the default fit usually reaches a higher log posterior than the oracle. The
  posterior's best mode is then not near the true shocks.

### Network-informed shock probability

`network_shock_test.jl` simulates shocks with a probability specific to each
variable,

    logit π_jt = a₀ + a_b Σ_{l born at t} |ρ̃_{t,jl}| + a_d Σ_{l dying at t} |ρ_{t−1,jl}|,

with a₀ = −2.5 and a_b = a_d = 4. It fits three models: the matching network
model (`shock_covariates = :network`, prior N(0, 2²) on the coefficients), the
current counts model, and the network model started from the truth (oracle).
The design is p = 10, k = 5, τ_a = 1.5 and `minimum_active = 6`, with 20
trajectories. The CSV is
`results/experiment2/network_p10_k5_tau150_min6.csv`.

| | network fit | counts fit | oracle |
|---|---|---|---|
| shock AUROC | 0.50 ± 0.09 | 0.66 ± 0.07 | 0.98 ± 0.02 |
| shock recall / precision | 0.07 / 0.11 | 0.07 / 0.11 | 0.97 / 1.00 |
| off-diagonal RV | 0.72 | 0.72 | 0.86 |
| estimated a_b / a_d (truth 4 / 4) | 0.01 / −0.29 | | 2.52 / 3.07 |

With the loading link, `link=loadings`, the link is
|⟨λ_{t−1,j}, λ_l⟩|, with true slopes 0.5. The CSV is
`results/experiment2/network_loadings_p10_k5_tau150_min6.csv`.

| | network fit | counts fit | oracle |
|---|---|---|---|
| shock AUROC | 0.53 ± 0.07 | 0.61 ± 0.07 | 0.99 ± 0.02 |
| shock recall / precision | 0.07 / 0.09 | 0.08 / 0.09 | 0.99 / 1.00 |
| off-diagonal RV | 0.68 | 0.69 | 0.85 |
| estimated a_b / a_d (truth 0.5 / 0.5) | 0.02 / −0.09 | | 0.47 / 0.47 |

With either link, the network fit computes its covariates from its own
estimate of the network.
At k = 5 that estimate is not good enough to locate the shocks, so the slopes
are estimated near zero and the covariates add no information. The counts
model ranks shocks better (AUROC 0.66) because the true shocks cluster at
event times, which its covariates capture without relying on the estimated
network.

### Fitting strategies

`fit_strategies.jl` compares fitting strategies on the k = 2 trajectories of
the oracle check (p = 10, τ_a = 1.5, `minimum_active = 6`, 20 trajectories).
The CSV is `results/experiment2/strategies_p10_k2_tau150_min6.csv`.

| strategy | shock AUROC | recall | off-diagonal RV | log posterior ≥ oracle's |
|---|---|---|---|---|
| default | 0.59 | 0.10 | 0.78 | 3 of 20 |
| best of 5 restarts | 0.60 | 0.09 | 0.79 | 7 of 20 |
| annealing of τ_i over 50 iterations | 0.64 | 0.01 | 0.80 | 20 of 20 |
| all-inactive start | 0.64 | 0.00 | 0.80 | 20 of 20 |
| all-inactive start + annealing | 0.64 | 0.01 | 0.80 | 20 of 20 |
| oracle (EM from the truth) | 0.94 | 0.87 | 0.94 | |

Annealing and the all-inactive start reach a log posterior about 146 above
the oracle's, the median over trajectories, while calling almost no shocks.
The MAP objective therefore favours solutions without shocks over the true
ones, and better optimization alone makes detection worse rather than better.

### MCMC

`mcmc_check.jl` runs `MCMC_time_varying` (Metropolis-within-Gibbs, with 2000
burn-in and 3000 sampling sweeps) on the k = 2 trajectories of the strategy
comparison. Each trajectory has two chains, one started from the EM fit and
one from the truth. The CSV is
`results/experiment2/mcmc_p10_k2_tau150_min6.csv`.

| | EM | MCMC from EM fit | MCMC from truth |
|---|---|---|---|
| shock AUROC | 0.59 ± 0.06 | 0.64 ± 0.06 | 0.68 ± 0.07 |
| recall / precision at γ > 0.5 | 0.10 / 0.10 | 0.12 / 0.27 | 0.19 / 0.44 |
| mean γ, true shocks / non-shocks | 0.10 / 0.09 | 0.22 / 0.11 | 0.25 / 0.08 |
| RV, full matrix | 0.83 | 0.89 | 0.91 |
| RV, off-diagonal | 0.78 | 0.85 | 0.87 |

- The posterior mean improves precision recovery over the EM point estimate,
  with off-diagonal RV 0.85 against 0.78.
- Shock detection improves but stays weak. The posterior mass separates
  shocks from non-shocks only modestly at this signal level.
- The two chains agree to within 0.05 in AUROC in 12 of 20 trajectories, with
  a median difference of 0.04. The chain started from the truth does slightly
  better, so mixing is incomplete; the flip move is accepted about 2–3% of
  the time.

the replicas reduce to independent EM runs at different temperatures, and the
best state always comes from the hottest one.

| | AUROC | recall | precision | mean γ, shocks / non-shocks | off-diagonal RV | log posterior |
|---|---|---|---|---|---|---|

### Recalibrated EM: fixed shock probability and wider spike

`tempered_em_check.jl` with `TEMPERED_EM_FIXED_PI=0.1`,
`TEMPERED_EM_TAU_INACTIVE=0.3` and likelihood-only tempering (forced
exchanges) fixes π = 0.1 and sets τ_i = 0.3 in both the EM fit and the
tempered replicas. Five trajectories, in
`results/experiment2/tempered_em_calibrated_pi010_tau030_p10_k2_tau150_min6.csv`:

| | AUROC | recall | mean γ, shocks / non-shocks | off-diagonal RV | RV |
|---|---|---|---|---|---|
| EM, π learned, τ_i = 0.075 | 0.585 | 0.090 | 0.091 / 0.071 | 0.739 | 0.817 |
| EM, π = 0.1, τ_i = 0.3 | 0.610 | 0.000 | 0.005 / 0.007 | 0.822 | 0.869 |
| tempered EM, π = 0.1, τ_i = 0.3 | 0.616 | 0.000 | 0.005 / 0.005 | 0.824 | 0.869 |

With π fixed, every shock probability sits at about 0.005. That is the
E-step value for a loading change estimated at zero: logit γ = logit π −
k log(τ_a / τ_i) ≈ −5.4. The point estimates of the loading changes stay near
zero for true shocks too, so the E-step, which judges shocks from those point
estimates, cannot detect them. The precision matrices are recovered better
than by the default fit.

### Reset prior: shocks centred at zero

`reset_check.jl` compares two definitions of a shock. Both use the same
spike, D_jt ~ N(0, τ_i²/k I), when there is no shock:

- **jump** (`shock_center = :previous`, the paper's model):
  λ_jt = λ_j,t−1 + D_jt, with D_jt ~ N(0, τ_a²/k I);
- **reset** (`shock_center = :zero`): λ_jt ~ N(0, τ_a²/k I), independent of
  λ_j,t−1, like a birth.

Each of seeds 1–5 is simulated twice, with the same births, deaths and shock
times: once with `shock_type = :jump` and once with `shock_type = :reset`.
Both models are fitted to both data sets, by EM and by plain MCMC (1000 + 2000
sweeps) started from the EM fit.

Settings: p = 10, k = 2, τ_a = 1.5, τ_i = 0.075, π learned, minimum_active = 6.
Under the reset prior, EM updates the loadings by level moves (one time
point) and segment moves (up to the next shock). MCMC shifts whole regimes
between shocks, so each move changes a single prior term. Results are in
`results/experiment2/reset_p10_k2_tau150_min6.csv`; table entries are means
over the 5 seeds.

| data | model | method | AUROC | recall / precision at γ > 0.5 | recall / precision at γ > 0.2 | RV | RV, off-diagonal |
|---|---|---|---|---|---|---|---|
| jump | jump | EM | 0.585 | 0.09 / 0.11 | 0.09 / 0.11 | 0.817 | 0.739 |
| jump | jump | MCMC | 0.598 | 0.13 / 0.30 | 0.20 / 0.22 | 0.871 | 0.817 |
| jump | reset | EM | 0.575 | 0.07 / 0.24 | 0.07 / 0.24 | 0.813 | 0.735 |
| jump | reset | MCMC | 0.589 | 0.05 / 0.33 | 0.10 / 0.28 | 0.853 | 0.785 |
| reset | jump | EM | 0.550 | 0.08 / 0.08 | 0.08 / 0.08 | 0.638 | 0.471 |
| reset | jump | MCMC | 0.615 | 0.11 / 0.18 | 0.33 / 0.18 | 0.723 | 0.570 |
| reset | reset | EM | 0.614 | 0.10 / 0.17 | 0.10 / 0.17 | 0.604 | 0.420 |
| reset | reset | MCMC | 0.673 | 0.03 / 0.22 | 0.33 / 0.22 | 0.752 | 0.600 |

Findings:

- **Matching the model to the data helps detection a little.**
  - On reset data, the reset model has the best AUROC (MCMC 0.67 against 0.62
    for the jump model).
  - On jump data, the jump model is slightly better.
  - These differences are within about one standard error with 5 seeds
    (about 0.04).
- **The reset prior does not solve detection.** Recall at γ > 0.5 stays at or
  below 0.13 in every cell.
- **The reset model is more conservative on jump data.** It calls fewer
  shocks, with higher precision and lower recall.
- **Precision matrices are much harder to recover from reset data** (RV,
  off-diagonal, 0.42–0.60 against 0.74–0.82). After a reset the new loadings
  share nothing with the past, so each regime is estimated only from its own
  time points, at one observation per time.

## Evaluation metrics

`active_precision_errors` reports, at each time point and on the active set:

- `rv`: RV coefficient of the full precision matrices;
- `offdiagonal_rv`: RV on the off-diagonal entries only;
- `partial_correlation_rv`: RV on the off-diagonal partial correlations;
- relative Frobenius error, mean absolute error and RMSE.

The full-matrix RV is dominated by the diagonal. It can stay high when the
off-diagonal structure is poorly recovered, so report the off-diagonal or
partial-correlation RV alongside it.

## Implementation notes

- **Binary-splitting initialization.** `masked_segment_bic` is a deliberate
  pseudo-BIC, not a standard BIC; see its docstring. In practice it accepts
  every split, so the recursion is stopped by `min_segment_length` and
  `changepoint_max_depth`.
- **Minimum active set.** `generate_birth_death_times(...; minimum_active)`
  postpones a death that would leave fewer than `minimum_active` variables.
  Use `k + 1` to respect assumption (S4), p_t > k. The default of 1 only rules
  out empty time points. `EM_time_varying` warns when the data contain time
  points with p_t ≤ k or p_t = 0.
- **Births in Experiment II.** Each variable has a single active spell, so the
  number of births per trajectory is fixed: p minus the number initially
  active. Only the birth times are random.
- **`legacy/`** holds earlier MCMC samplers: `mcmc_sampler.jl`,
  `hmm_sampler_backup.jl` and `toy_example_sampler.R`. They are not used by the
  current estimator.
