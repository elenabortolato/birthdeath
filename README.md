# Birth–Death Gaussian Graphical Models

Code for *Birth–Death Gaussian Graphical Models for Structurally Evolving
Systems* (Bortolato, Hansen, Rossell). The model is a Gaussian graphical model
whose set of variables changes over time. The precision matrix on the active
set is low rank plus diagonal, and a spike-and-slab prior on rowwise loading
changes, informed by birth and death counts, drives its evolution. Estimation
uses a generalized EM algorithm.

The scripts for Experiment I (piecewise-constant precision), Experiment III
(endogenous exit), the competitor fits and the prior plots are not in the
repository yet.

## Setup

Install Julia 1.10 or later, then from the repository root:

```bash
julia --project=. -e 'using Pkg; Pkg.instantiate()'
```

`src/BirthDeathGraphicalModels.jl` loads Plots for its plotting helpers. On a
machine without a display, set `GKSwstype=100` before running.

## Running the experiments

All commands are run from the repository root.

**Experiment II.** One CSV row per simulated trajectory:

```bash
julia --project=. experiments/birthdeath/run_experiment2.jl \
    p=10 seeds=1:20 tau_active=0.75 minimum_active=6 \
    out=results/experiment2/p10_tau075_min6.csv
```

| Argument | Meaning | Default |
|---|---|---|
| `p` | number of variables (10 or 50) | 10 |
| `seeds` | `a:b` range or comma-separated list | `1:5` |
| `tau_active` | fitted active innovation scale τ_a | 0.75 |
| `minimum_active` | lower bound on the number of active variables p_t | k + 1 = 6 |
| `out` | output CSV path | none, prints only |

Every other setting is the paper's, and is fixed in the script.

**Constant precision, p = 5:**

```bash
julia --project=. experiments/constant_precision/run_constant_precision_p5.jl
```

It writes summaries and per-time metrics to
`experiments/constant_precision/constant_precision_p5_output/`.

## Results: Experiment II, p = 10

Twenty trajectories per setting, generated by `run_experiment2.jl`. The CSVs
are in `results/experiment2/`. Values are mean ± SD across trajectories; metrics
are computed on the full time-varying active sets.

| | `p10_min1_tau075` | `p10_min6_tau075` | `p10_min6_tau150` |
|---|---|---|---|
| `minimum_active` | 1 | 6 (= k + 1) | 6 |
| fitted τ_a | 0.75 | 0.75 | 1.5 |
| smallest p_t | 2.1 ± 1.1 | 6 | 6 |
| births / deaths per trajectory | 3 / 7.7 | 3 / 4 | 3 / 4 |
| RV, full matrix | 0.87 ± 0.04 | 0.85 ± 0.04 | 0.84 ± 0.04 |
| RV, off-diagonal | 0.71 ± 0.15 | 0.71 ± 0.12 | 0.70 ± 0.11 |
| RV, partial correlations | 0.73 ± 0.13 | 0.76 ± 0.09 | 0.74 ± 0.08 |
| relative Frobenius error | 0.65 ± 0.08 | 0.65 ± 0.07 | 0.62 ± 0.07 |
| shock AUROC | 0.62 ± 0.05 | 0.62 ± 0.05 | 0.60 ± 0.05 |
| shock precision / recall | 0.09 / 0.04 | 0.11 / 0.07 | 0.09 / 0.07 |
| shock specificity | 0.96 | 0.94 | 0.93 |
| a₀ (truth −2.5) | −3.27 ± 0.39 | −2.76 ± 0.26 | −2.63 ± 0.32 |
| a_b / a_d (truth 0.8 / 0.8) | 0.50 / 0.23 | 0.44 / 0.43 | 0.40 / 0.39 |

- Precision recovery is stable across settings. The off-diagonal RV is about
  0.15 below the full-matrix RV.
- Shock detection is close to chance in all three settings. Neither keeping
  p_t > k nor matching τ_a to the true shock scale improves it.

### Oracle check: why shock detection is poor

`oracle_check.jl` compares the default fit with generalized EM started from the
true parameters ("oracle"). The design is p = 10, τ_a = 1.5 (the true shock
scale) and `minimum_active = 6`, with 20 trajectories per rank. The CSVs are
`results/experiment2/oracle_p10_k*_tau150_min6.csv`.

| | k = 5 | k = 2 |
|---|---|---|
| shock AUROC, oracle / default | 0.99 / 0.60 | 0.94 / 0.59 |
| shock recall, oracle / default | 0.98 / 0.07 | 0.87 / 0.10 |
| off-diagonal RV, oracle / default | 0.86 / 0.70 | 0.94 / 0.78 |
| oracle reaches a higher log posterior than default | 7 of 20 | 17 of 20 |

- Started from the truth, the EM stays there: the data separate shocks from
  non-shocks.
- With k = 2 the decomposition is identified for every p_t ≥ 5. There the
  default fit usually lands in a worse mode than the oracle, so the
  initialization and optimization are what lose the shocks.
- With k = 5 and p_t between 6 and 8 the decomposition is not identified, and
  the default fit usually reaches a higher log posterior than the oracle. The
  posterior's best mode is then not near the true shocks.

### Network-informed shock probability

`network_shock_test.jl` simulates shocks with a probability specific to each
variable,

    logit π_jt = a₀ + a_b Σ_{l born at t} |ρ̃_{t,jl}| + a_d Σ_{l dying at t} |ρ_{t−1,jl}|,

with a₀ = −2.5 and a_b = a_d = 4. It fits three models: the matching network
model (`shock_covariates = :network`, prior N(0, 2²) on the coefficients), the
current counts model, and the network model started from the truth (oracle).
The design is p = 10, k = 5, τ_a = 1.5 and `minimum_active = 6`, with 20
trajectories. The CSV is
`results/experiment2/network_p10_k5_tau150_min6.csv`.

| | network fit | counts fit | oracle |
|---|---|---|---|
| shock AUROC | 0.50 ± 0.09 | 0.66 ± 0.07 | 0.98 ± 0.02 |
| shock recall / precision | 0.07 / 0.11 | 0.07 / 0.11 | 0.97 / 1.00 |
| off-diagonal RV | 0.72 | 0.72 | 0.86 |
| estimated a_b / a_d (truth 4 / 4) | 0.01 / −0.29 | | 2.52 / 3.07 |

The network fit computes its covariates from its own estimate of the network.
At k = 5 that estimate is not good enough to locate the shocks, so the slopes
are estimated near zero and the covariates add no information. The counts
model ranks shocks better (AUROC 0.66) because the true shocks cluster at
event times, which its covariates capture without relying on the estimated
network.

## Evaluation metrics

`active_precision_errors` reports, at each time point and on the active set:

- `rv`: RV coefficient of the full precision matrices;
- `offdiagonal_rv`: RV on the off-diagonal entries only;
- `partial_correlation_rv`: RV on the off-diagonal partial correlations;
- relative Frobenius error, mean absolute error and RMSE.

The full-matrix RV is dominated by the diagonal. It can stay high when the
off-diagonal structure is poorly recovered, so report the off-diagonal or
partial-correlation RV alongside it.

## Implementation notes

- **Binary-splitting initialization.** `masked_segment_bic` is a deliberate
  pseudo-BIC, not a standard BIC; see its docstring. In practice it accepts
  every split, so the recursion is stopped by `min_segment_length` and
  `changepoint_max_depth`.
- **Minimum active set.** `generate_birth_death_times(...; minimum_active)`
  postpones a death that would leave fewer than `minimum_active` variables.
  Use `k + 1` to respect assumption (S4), p_t > k. The default of 1 only rules
  out empty time points. `EM_time_varying` warns when the data contain time
  points with p_t ≤ k or p_t = 0.
- **Births in Experiment II.** Each variable has a single active spell, so the
  number of births per trajectory is fixed: p minus the number initially
  active. Only the birth times are random.
- **`legacy/`** holds earlier MCMC samplers: `mcmc_sampler.jl`,
  `hmm_sampler_backup.jl` and `toy_example_sampler.R`. They are not used by the
  current estimator.
